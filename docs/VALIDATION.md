# Phase 0 验证结论

**状态：未开始。** 本文件是三个技术假设的验证台账。在每个假设被实测之前，
不要基于「它应该能行」去写依赖它的代码 —— 这三条的结论会直接改变架构。

## 假设 A：首页卡片能提供哪些判定材料

| 问题 | 结论 | 证据 |
| --- | --- | --- |
| 卡片的选择器是什么（用什么稳定属性定位） | 待验证 | |
| 笔记 ID 从哪取、形态与长度 | 待验证 | |
| 首页数据里**有没有**正文（`desc`） | 待验证 | |
| 页面数据是否在页面世界（需 MAIN world 才能读） | 待验证 | |
| 滚动后 DOM 节点是否被回收复用 | 待验证 | |
| 首页 URL 形态：`/` 与 `/explore`，详情页是否为 `/explore/{id}` | 待验证 | |

**影响**：决定 OCR 是主路径还是备选（基线 4.4 的措辞）、决定 `extractor.ts` 与
`feedObserver.ts` 的实现、决定 manifest 的 `matches` 与 `routeGate` 的路径集合。

## 假设 B：封面图能被取到并识别

| 问题 | 结论 | 证据 |
| --- | --- | --- |
| content script 里 `canvas.toDataURL()` 是否抛 SecurityError（画布污染） | 待验证 | |
| service worker `fetch` 图片 CDN 是否 200（需 host_permissions 覆盖真实域名） | 待验证 | |
| 是否被防盗链拦截（403），是否需要 declarativeNetRequest 改 Referer | 待验证 | |
| tesseract.js `chi_sim` 对 10 张真实封面的识别质量 | 待验证 | |
| 单张识别耗时（用于定并发与性能预算） | 待验证 | |

**影响**：决定「标题 + OCR」降级链路是否存在。若整条不可用，V1 要么只靠标题
（判定强度会明显下降），要么重新定义基线的输入假设。
