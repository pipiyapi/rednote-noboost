# 技术决策记录（ADR）

一条决策一个条目，写清「决定了什么、为什么、放弃了什么、什么时候该重新考虑」。
目的是让半年后的自己（或接手的人）不用重新推一遍。

模板：

```text
## ADR-000 标题
状态：已采纳 / 待定 / 已废弃
决定：一句话
背景：约束是什么
理由：为什么这个选择更好
放弃的方案：以及为什么不用
重新考虑的条件：什么情况下要翻案
```

---

## ADR-001 使用 esbuild 打包，而不是直接裸跑源码

**状态：** 已采纳
**决定：** 用 `build.mjs` 把 TypeScript 打包成 `extension/dist/content.js`（iife）与
`dist/service-worker.js`（esm）等产物。
**背景：** manifest 的 `content_scripts` 不支持 `"type": "module"`，content script
无法静态 `import` 共享模块；只有 background service worker 支持 ESM。
**理由：** 本项目有 9 个模块、多人多 Agent 并行，「共享逻辑复制一份」必然漂移 ——
参考项目已经踩过：真实扩展显示了内部 reasonCode，离线夹具却显示中文标签。
**放弃的方案：** 手抄一份共享逻辑（省掉构建步骤，但换来永久的一致性债）。
**重新考虑的条件：** 无。构建成本只有几十行配置。

## ADR-002 扫描队列与状态放在 content script，service worker 保持无状态

**状态：** 已采纳
**决定：** service worker 只做「读 Key + 发请求 + 决策」；队列、进度、判定状态
全部活在 content script。
**背景：** MV3 的 service worker 空闲约 30 秒会被浏览器回收，内存里的一切都会消失。
**理由：** content script 的生命周期等于页面生命周期，能稳定承载队列与统计。
**放弃的方案：** 队列放 worker（看起来更「后台」，但滚几分钟进度就归零）。
**重新考虑的条件：** 若将来需要跨标签页共享状态，改用 `chrome.storage.session`。

## ADR-003 去重键与状态键都用 noteId，不用 DOM 节点

**状态：** 已采纳
**决定：** `feedObserver` 用 WeakMap 记录节点当前 noteId（只管性能），`cardController`
用 `Map<noteId, Entry>` 做身份级状态；节点重挂时按 noteId 重放外观。
**背景：** 瀑布流会虚拟化/回收 DOM 节点，同一节点后来可能装另一篇笔记。
**理由：** 身份建在节点上会导致「新笔记永远不被判定」且完全无报错。
**重新考虑的条件：** 无。

## ADR-004 渲染只做可逆叠加，且用 outline 不用 border

**状态：** 已采纳
**决定：** 模糊 = 叠加层 + `outline`；绝不删除或改写笔记自身内容；离开首页时
全部移除。手动暂停只停止新任务，已得到的判定外观保留。
**理由：** `border` 会改变盒子尺寸导致信息流重排跳动；改写原内容无法还原。
**重新考虑的条件：** 若实测发现叠加层被页面自身层级遮挡，改用 Shadow DOM 宿主。

## ADR-005 两个过滤器共用一次判定请求，开关只影响渲染

**状态：** 已采纳
**决定：** 一次请求同时取商业类与情绪类信号；两个开关只决定「命中结果是否渲染成模糊」。
**理由：** 同一篇笔记只判定一次，切换开关不需要重新调用 API，省成本也省延迟。
**放弃的方案：** 每个开关各发一次请求（成本翻倍，且两套 rubric 更容易漂移）。
**重新考虑的条件：** 若实测发现两类问题在同一请求里互相干扰，拆成两次请求。

## ADR-006 V1 不建后端，API Key 只在本地

**状态：** 已采纳（来自基线第 6 节）
**决定：** 每位开发者使用自己的 Key，只存 `chrome.storage.local`，只有 worker 读取。
**理由：** 内部验证范围，无分发需求；共享密钥才需要后端保护。
**注意：** MV3 中同一扩展的各上下文都能读 `chrome.storage`；保护来自隔离世界
（页面脚本不可达），而不是存储隔离。因此仍要遵守「不把 Key 传给 content script」。

## ADR-007 默认只开「商业推广」过滤器

**状态：** 待定（需协作者确认后写入基线 4.8）
**决定：** 首次安装 `filterCommercial = true`、`filterEmotional = false`。
**理由：** 情绪类误判代价最高（可能压制真实求助、维权、情绪表达），标定也最难；
先建立对商业判定的信任，再决定是否默认开启。
**重新考虑的条件：** 带人工标签的评估显示情绪类 precision 足够高。

## ADR-008 失败不是结论：失败必须可重试

**状态：** 已采纳
**决定：** `cardController.attach()` 对 `error` 状态返回 false，使失败的笔记在下次扫描
（暂停后再开始、或滚动触发重新发现）时重新排队；重复请求由队列按 noteId + 代次去重。
**背景：** `attach()` 原先把任何非 `undetermined` 的结论都当成「已处理」，而 `error` 也是
一种结论，于是一次限流或超时就把该笔记永久钉死——只有刷新整页才能重试。
**理由：** 失败是「没拿到答案」，不是「已经答过了」。fail open 只保证不误伤内容，
不代表可以放弃重试。
**代价：** 失败的笔记会被反复请求。当前靠手动「暂停 → 开始」或滚动重新发现来触发，
不会自动重试；若将来加自动重试，必须带退避与次数上限。
**重新考虑的条件：** 若出现「一直失败一直重试」导致 API 调用量失控，改为带退避的有限重试。

## ADR-009 「已判定」按笔记计数，且必须展示失败原因

**状态：** 已采纳
**决定：**
1. `ScanStats.errorsByKind` 按 `FailureKind` 分桶，面板只展示实际出现过（>0）的原因；
2. 结论落定走 `scanStats.recordDecision()`：重试覆盖旧结论时先回退旧桶，
   因此「已判定」始终等于「有结论的笔记数」，各类之和恒等于它。
**背景：** 面板原先只显示一个「失败 29」。`auth`（换 Key）／`rate_limit`（降并发）／
`parse`（改解析）／`timeout`（重试）的处置方式完全不同，只给总数既无法排查，
也判断不出该改代码还是改配置。
**理由：** 可观测性不是锦上添花——没有失败原因，协作双方都只能靠猜。
**口径约束（改动前请先看）：** `undetermined` 永不计入任何桶；重试不得虚增「已判定」。
**回退方式：** 面板的失败明细整块隐藏（失败为 0 时），不增加日常噪音。

## ADR-010 PP-OCRv6 Small 是唯一默认 OCR

**状态：** 已采纳
**决定：** 每篇首页卡片默认先用 `PP-OCRv6_small_det + PP-OCRv6_small_rec` 识别封面，
再把标题与 OCR 合并为一次 Jev 输入；不保留 Tesseract 或 PP-OCRv5 运行分支。
**理由：** 同一组 7 张真实封面中 v6 small 达到 7/7 可用，且约 30 MiB 模型仍在本地扩展可接受范围。
**运行方式：** 模型由 MV3 offscreen document 承载，单实例、串行推理；首次下载后复用浏览器缓存。
**降级：** OCR 失败时继续用标题调用 Jev，不让采集失败变成过滤结论。
**重新考虑的条件：** 真实页面长时间滚动出现不可接受的 CPU、内存或吞吐问题。

## ADR-011 检测历史只保留当前页面会话

**状态：** 已采纳
**决定：** content script 按 noteId 保存 OCR 结果、Jev 输入/原始输出、耗时和最终判定，
并在 popup 中按帖子展示；刷新或关闭标签页后自然清空，不写入长期本地存储。
**理由：** 调试与建立判定信任需要完整可见的因果链，但长期保存浏览记录超出 V1 隐私边界。
**安全边界：** 审计结构永不包含 API Key 或 Authorization 请求头。
