# OCR 健康检查与 MV3 兼容修复

## 面板行为

- 打开面板时检查 OCR，每 3 秒更新一次；首次检查会加载 PP-OCRv6 Small。
- 黄色「检查中」：加载模型并用内置文字画布执行实际识别，禁止开始扫描。
- 绿色「健康」：模型初始化及文字识别自检通过，允许开始扫描；启动前再次查询状态。
- 红色「不可用」：显示加载、连接或识别错误，禁止开始扫描；可点击「重新检查」。
- 加载或自检超过两分钟显示超时提示；后台若最终完成自检，状态会恢复。
- 健康不等于每张封面都能识别正确，也不代表 JEV API 可用。

## 本次报错根因与修复

截图中的连接失败是后果：OpenCV 的 Emscripten 绑定在模块加载期间动态构造
JavaScript 函数，被 MV3 CSP 拦截，消息监听器因此没有注册。

1. 构建时将 OpenCV 的命名函数、动态调用、类型转换调用及方法调用四处工厂
   转换为普通闭包，保留参数转换、返回值转换与析构逻辑；不修改 node_modules。
2. 转换器遇到不匹配的依赖结构或残留动态执行时直接让构建失败，升级依赖必须复查。
3. ONNX Runtime 使用 WASM-only 入口，不打包不使用的其他后端。
4. 消息监听器先注册，SDK 延迟导入，使启动失败能够返回可见的诊断信息。
5. 后台创建完成到监听器注册之间做有限次数重试。

不增加 `unsafe-eval`，保留现有扩展安全策略。

## 验证与限制

- 53 项自动化测试通过，类型检查与构建通过。
- 在禁止字符串代码生成的隔离环境中，真实 OpenCV WASM 成功加载，Mat 创建、
  颜色转换和释放通过；这不是仅用替身验证 OpenCV。
- 健康生命周期、失败/重试、空输出、扫描按钮门禁使用模拟模型/DOM 做回归测试。
- 尚未在用户 Chrome 中完成真实 PP-OCRv6 下载与封面识别端到端验证。
- 本轮未完成真实面板截图审查及窄屏溢出测量，不将模拟 DOM 测试视为视觉验收。

## 更新使用

在扩展管理页重新加载本项目扩展，再刷新小红书页面。打开面板等待 OCR 变为
绿色「健康」后再开始扫描。历史中的旧失败记录不会因为修复自动变成成功记录。
