# 样本（samples）

JSONL，一行一条。建议字段：

```json
{
  "id": "EX-001",
  "split": "dev",
  "label": "filter_commercial",
  "rationale": "一句话说明为什么这样标",
  "title": "……",
  "ocr_text": "……",
  "source": "title+ocr",
  "note_id_hash": "sha256 前 12 位"
}
```

## 标注 provenance（必须写清楚，否则这批数字不能用）

在每批样本文件顶部（或同目录的说明文件里）记录：

- 样本从哪来：自己写的虚构样本 / 经同意使用的真实笔记；
- **谁标的**：人工逐条标注，还是 AI 起草后批量接受；
- 有没有被用于调阈值（调参集 / 留出集）；
- 标注时间与标注口径版本。

> **为什么较真这件事：** 如果标签是 AI 起草的，而 rubric 问题又来自同一批写作套路
> 目录，那么"模型和标签一致"只是在测量模型与那套启发式的一致，属于**循环自证**，
> 不能作为准确率证据。参考项目在自己的评估报告里明确标注了这一点 —— 这是正确的
> 做法，请沿用。

## 脱敏要求

- **绝不**包含真实 API Key。
- 真实笔记需经作者同意；否则一律使用虚构样本。
- 不记录作者昵称、主页链接等可识别信息；如需跨会话关联，只存哈希。
- 建议不提交封面图原图（体积与隐私双输），只保留 OCR 文本。

## 规模建议

30 条足够跑通链路与暴露明显问题，但不足以支撑阈值结论。
建议起步：调参集 30–50 条（商业 / 情绪 / 正常 / 边界各占相当比例），
留出集 20–30 条**在调阈值期间完全不看**。
