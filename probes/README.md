# 探针（probes）

Phase 0 的一次性验证脚本。它们**不是产品代码**，不进打包产物，但结论要写进
`docs/VALIDATION.md` 并保留脚本本身作为可复现的证据。

## 为什么要有这一层

这个项目所有真正的风险都不在代码组织上，而在**页面与外部服务的实际形态**上：

1. 首页卡片里到底能不能拿到正文？
2. 封面图能不能取到字节并识别出可用文字？
3. noteId 是否稳定、DOM 节点是否会被回收复用？
4. Jev 对中文笔记的答案分布长什么样（阈值要靠它定）？

这四条任何一条不成立，都会改变架构。在写产品代码之前花几小时验掉，比事后返工便宜得多。

## 计划中的三个探针

| 脚本 | 怎么跑 | 要回答的问题 |
| --- | --- | --- |
| `probe-page.js` | 在首页控制台粘贴执行 | 卡片选择器、noteId 形态、首页数据里有无正文、滚动后节点是否复用、URL 形态 |
| `probe-ocr.js` | 在首页控制台执行 + 扩展侧配合 | canvas 是否被污染、worker 能否取到图片字节、是否有防盗链、OCR 精度与耗时 |
| `probe-jev.mjs` | Node 运行（`.env` 提供 Key） | 请求是否打通、`noul` / `score` 的答案分布、中文 rubric 措辞是否合适、延迟与 token 用量 |

## 约定

- 探针只做读取与打印，**不做任何页面改动、不发送账户操作、不自动打开笔记**。
- 输出里不要包含真实用户信息或 API Key；页面结构片段贴进文档前先脱敏。
- 每个探针的结论都要能回答「这改变了我原来的哪个假设」。
